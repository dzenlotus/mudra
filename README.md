# Mudra

Сохраняемый AI harness на основе Ghanta и Vajra. Предварительная версия для Mac с Apple Silicon.

**[Скачать Mudra](https://github.com/dzenlotus/mudra/releases/download/v0.1.0-preview.20261022.2/mudra-macos-arm64-graph-preview.zip)** · [Страница выпуска](https://github.com/dzenlotus/mudra/releases/tag/v0.1.0-preview.20261022.2)

## Установка и запуск

1. Распакуйте архив и откройте `Install.command`.
2. Откройте новый Терминал, перейдите в нужную папку и введите `mudra`.
3. Настройте свои LLM и embedding API, затем напишите задачу.

Установка копирует бинарник в `~/.local/bin/mudra` и добавляет путь в настройки zsh. Архив можно переместить. Без установки можно открыть `Mudra.command` или запустить `./bin/mudra chat`.

```sh
mudra                         # глобальные знания; действия в текущей папке
mudra -C /path/to/project      # глобальные знания; действия в указанной папке
mudra --local                 # глобальные знания + расширение проекта
mudra --local -C /path/to/project
mudra scope                   # выбранная область и расположение данных
```

Глобальная база используется всегда по умолчанию, включая запуск с `-C`.
Рабочая папка определяет, с какими файлами выполняется задача.

В режиме `--local` новые знания и переопределения записываются в `.mudra` проекта. Перед новой задачей расширение получает глобальные обновления, сохраняя свои изменения и удаления. Настройки проекта наследуют глобальные значения. `mudra --local sync` обновляет глобальную часть явно.

Обратный перенос — явная команда после проверки:

```sh
mudra --local promote --rule RULE_NAME --case TRUSTED_CASE_ID
```

Переносятся выбранные правила с необходимыми параметрами, процедурами и контекстными связями. Проверяются независимый ожидаемый результат и фактический вызов выбранного правила. При конфликте или отсутствии проверки запись отклоняется. В этой версии такая проверка поддерживает безопасные выражения и композиции; SOURCE, процессы и LLM для переноса отклоняются. Файлы проекта, разговоры, факты задач и журнал не публикуются в глобальную базу.

## Диалог

Enter отправляет запрос. Shift+Enter добавляет строку; Ctrl+J — перенос для терминалов без отдельного Shift+Enter. Дождитесь открытия редактора перед вставкой первого запроса после настройки.

- `/connect` — добавить OpenAI-совместимого провайдера.
- `/models` — каталог моделей провайдера, поиск, выбор стрелками и Enter. Ctrl+R обновляет список, Esc закрывает окно.
- `/settings` — лимиты задачи, модели, окно контекста, кеш и API.
- `/scope` — область знаний и рабочая папка; `/sync` — обновить расширение проекта.
- `/status`, `/sessions`, `/journal` — состояние, сессии и фоновая обработка.
- `/resume` — продолжить ту же задачу; `/new` — новая беседа; `/exit` — выход.

LLM выбирается отдельно от эмбеддера. Поддерживаются корпоративные OpenAI-совместимые API. Ключи берутся из окружения или Keychain. Настройки и выбор модели сами не продолжают приостановленную задачу.

F4 показывает ход работы и реальные вызовы процедур Vajra. F5 разворачивает 3D-граф текущего пути, F6 показывает список узлов и связей. Для построчного диалога: `mudra chat --plain`.

На карте — тонкие связи и короткие подписи возле узлов. Полное имя появляется при выборе; выбранные связи выделяются. Объёмные узлы, поворот и полный состав пути сохранены. Если мини-карте тесно, F5 разворачивает её, а F6 показывает все имена и связи.

Для запуска обновления откройте `Mudra.command` из нового архива.

## Сервер без интерфейса

```sh
mudra inline --address 127.0.0.1:8787
mudra --local inline --address 127.0.0.1:8787
```

POST с текстом:

```json
{"instruction":"Прочитай файл notes.txt","context":{}}
```

Либо прямые параметры и цели для известных правил:

```json
{"facts":{"file":"notes.txt"},"goals":["content"]}
```

Ответ содержит статус, номер сессии, факты и записанные действия. CLI и сервер используют общий цикл Vajra/Гханты, настройки моделей и сохраняемый журнал.

Продолжение по конкретному номеру:

```json
{"action":"status","session":"SESSION_ID"}
{"action":"answer","session":"SESSION_ID","instruction":"Уточнение","facts":{}}
{"action":"resume","session":"SESSION_ID"}
{"action":"reconcile","session":"SESSION_ID","decision":"continue","evidence":"Результат действия проверен"}
```

Запуск интерфейса или сервера не возобновляет задачу автоматически. Продолжение использует исходную рабочую папку. Неопределённый результат внешнего действия требует явного решения; скрытого повторного исполнения нет.

## Данные и обновление

Глобальные данные находятся в `~/Library/Application Support/Mudra`. `MUDRA_HOME` задаёт другое абсолютное расположение. Разговоры глобального режима разделены по рабочим папкам; знания остаются общими.

Данные локального расширения находятся в `.mudra`. Старые проектные базы не удаляются. Чтобы открыть прежнюю обычную проектную базу, используйте `mudra --local -C /path/to/old/project`. Внешнюю общую базу можно явно подключить к глобальной области; автоматическое преобразование внешней базы в расширение проекта не выполняется.

Архив содержит только бинарник, два запуска, инструкцию и manifest. Пользовательских баз, настроек и ключей в нём нет. Rust и Python для запуска не нужны. Для создаваемых JavaScript-процедур требуется подходящий Node.js в PATH.

## Статус выпуска

Сведения о проверках и точные хеши приложены к выпуску в `runtime-receipt.json` и `SHA256SUMS`. Это preview без Developer ID и нотарификации Apple. Общая производственная готовность и задержка с произвольными моделями не установлены.
